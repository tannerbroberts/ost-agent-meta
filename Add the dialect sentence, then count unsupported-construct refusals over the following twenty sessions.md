#AssumptionTest #unvalidated #evidence/assertion

Put the sentence in the description — which engine, which constructs are absent, and the upstream reference — then leave it and count. Over the next twenty sessions that use the surface, count how many unsupported-construct refusals occur, and compare against the rate in the twenty sessions before the change. A person reads the refusals that still happen and marks whether each named a construct the sentence had already listed as absent.

The comparison is the cheap part. The marking is the part that needs a person: a refusal naming a construct the sentence did NOT cover is a description problem, and a refusal naming one it DID cover is the assumption failing, and only a reader can tell those apart.

**Lane: humans-required.**

**What this does NOT settle.** It measures whether the rate fell, not why. A fall could be the sentence being read, or it could be a change in the kind of searches those twenty sessions happened to run — this design has no control for that, and a supported verdict here should be read as encouraging rather than as established.

A person outside the building is the measurement here: A person must read each surviving refusal and judge whether the sentence had already covered the construct; no exit code separates a description gap from an unread description.
