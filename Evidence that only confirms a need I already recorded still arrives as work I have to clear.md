#Opportunity #unvalidated #evidence/observed
[[An evidence item can be filed as corroboration of a node that already exists]]

The self-observation channels work: this vault's own sessions are harvested mechanically and land as evidence without anyone carrying them in. What they mostly produce, though, is the same handful of frictions over and over — permission refusals for tools the surface withheld, `File has not been read yet` before an Edit, a clarifying question asked of a human who was not there. The tree already holds an opportunity for each of those.

The operator's problem is that corroboration has nowhere to go. Every item arrives in `unmappedEvidence` and stays there, because the only way to discharge an item is to create a node citing it as `source`. Confirming a need the tree already holds is not an option the surface offers. So each pass faces a choice between minting a near-duplicate opportunity — the debt merging exists to pay off — and leaving the item outstanding forever, where the next pass will read it again and face the same choice.

At the time of writing this the backlog stands at 76 items. It has only ever grown, and the growth is not a sign of 76 undiscovered needs; it is the same four needs observed 76 times. That count is the most interesting number in the corpus and the tree currently has no way to hold it: a need observed 76 times and a need observed once look identical once each has a node.

## What this is not

This is not a request to auto-map evidence. Deciding that a new observation is an instance of an existing need is a judgement, and one that is wrong in the direction that hides novelty. The need is for the judgement to be *recordable* — for "this confirms an existing need" to be a disposition an item can be given, so that frequency accumulates on the node it bears on and the queue reflects what is genuinely unread.
