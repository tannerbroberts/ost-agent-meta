#Assumption #unvalidated #evidence/assertion

**The belief, stated so it could be false (feasibility, guarding a safety property).** This candidate's objection is that it hands a constrained actor a way to shrink its own denominator — the one power this codebase withholds everywhere else. The proposed mitigation is a guard: a disposition is accepted only when it names a node that actually exists in the tree, so "reveals no need" cannot be a bare dismissal.

The belief is that such a guard is (a) expressible at the write boundary the way the other guards here are, and (b) actually binding — that there is no shape of disposition which drains a record while naming nothing real. It could be false in a specific and likely way: the `reveals no need` case *has* no node to name by definition, so either that case is refused entirely (and the largest class of records still never drains, which removes this candidate's whole advantage over its siblings) or it is exempted (and the exemption is the unguarded dismissal the objection was about, reintroduced through the door marked "no need").

That tension is the thing to test. A guard that only binds the easy case is not a mitigation, and this assumption is written so that outcome reads as a refutation rather than as a partial pass.
