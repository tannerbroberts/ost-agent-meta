#Assumption #unvalidated #evidence/assertion
[[Every stored friction record is labelled fired or not-fired at each candidate bar, with none left unlabelled]]

Feasibility belief, and it is the one that gates the sibling rather than competing with it.

The sibling assumption ("A single fixed per-run friction-count threshold separates sessions worth the operator's attention from ordinary recoverable noise") is settled by showing an operator a set of recorded sessions and each one's would-have-fired verdict. That study cannot be run until something produces those verdicts — so the human test beneath the sibling is currently blocked on a mechanism nobody has built, and nothing on the tree said so.

Stated so it could be false: for any candidate bar N, every friction record already stored can be labelled fired / not-fired without capturing anything new. If it is false — because the stored records do not preserve a per-run count, or preserve it only for some channels — then the human study cannot be assembled at any price, and this candidate is not merely unvalidated but untestable in its current form.

What makes it plausible: this vault's own transcript records already carry the count in their own text (`produced 9 friction events (tool_error ×8, retry ×1)`), and this pass read 377 such records outstanding. What makes it doubtful: a count that exists in a rendered sentence is not the same as a count a program can read, and no test asserts the number survives as data rather than as prose.
