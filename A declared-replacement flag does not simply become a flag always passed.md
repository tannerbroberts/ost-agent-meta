#Assumption #unvalidated #evidence/assertion
[[The overwrite refusal names the command at risk and still lets a correction through]]

**Kind: feasibility.**

**The belief, stated so it could be false.** A guard cleared by adding a parameter is a guard exactly as strong as the caller's inclination to stop and think. An agent clearing a 62-item backlog meets the refusal once, learns the parameter, and passes it thereafter — at which point the write path is identical to today's and the tree has bought a round trip.

The design question this turns on: whether the refusal can carry content that makes the caller reconsider rather than merely comply. Naming the flag teaches the way through; naming the *existing command* — the thing about to be destroyed, and the fact that it was written by a pass that could read the code — is information a caller has to actually weigh.

There is also a legitimate case the guard must not break. Correcting a wrong instrument is the same call shape as clobbering a good one, and the arguments alone cannot distinguish them.

**What would make it false.** A refusal that is cleared without the caller's decision changing — or a correction case that the guard blocks with no honest way through.
