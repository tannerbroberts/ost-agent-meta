# Founder directive: the tree must be able to self-organize its own nodes (2026-08-10)

Spoken in session by the founder. This one is a **directive about the product's
doctrine**, not only a theory — the founder owns the mandate and is explicitly
revising what "append-only" means. Evidence class for any claims herein: **assertion**.

**The directive.** "I want the tree to be able to self-organize its own nodes. This
goes against what has been said previously, 'it's append-only'. This isn't strictly
true." Wanted, in the founder's words:

- **Reclassify** nodes, and **up-rank / down-rank opportunities into entire classes
  of opportunities**.
- **Never delete content — version it.** The prohibition was always about loss, not
  about motion.
- **Justify all data by weaving misconceptions into the map that gets built — but
  legibly.** A corrected mistake stays on the map as a corrected mistake.

**The open question the founder names rather than answers.** "What is an agent to do
with an opportunity that was actually mis-construed given a fundamental
misunderstanding of reality? I don't know, but that's something it'll have to deal
with as it builds towards futures that haven't yet been proven."

**Session-context observations recorded alongside (agent's, same rung):**

1. This lands on existing doctrine: hygiene process P5 is "annotate, never delete,"
   and today a mis-construed opportunity can only accumulate Issues entries beside
   its unchanged self. The directive keeps the never-lose-content half and revokes
   the never-move half.
2. The tree already contains the need this serves: "Nothing kills a candidate, so
   every idea I have ever had is still alive" — removal-shaped; this directive adds
   the reorganization verbs (move, re-rank, reclass) that node's solutions lacked.
3. Versioning discipline already has precedent in-vault: the root Outcome's 2026-08-04
   body edit recorded "Git holds every one of them." Git-as-version-store may be the
   cheap mechanism; the legibility requirement (misconceptions visible on the map, not
   only in git) is the part git alone does not give.
4. Guard to carry into any build: reclassification is an agent-reachable write that
   changes what the tree *says*, so it must not become a laundering channel — a
   down-ranked node's evidence and history must survive the move, or "version it"
   quietly becomes deletion with extra steps.
