## What the tree surfaced, and why I took it without arguing

`.ost-agent/NEXT-BUILD.md` §2 was unambiguous: **run a test before building anything**, and
the test is [[Do the shipped sweeps actually find a planted instance]] — `compute-only`,
threshold pre-committed, the direct descendant of the eleventh pass's best finding.

It also carried an explicit prohibition I want to record as having been honoured, because it
was the tempting move: **do not build [[Every count states the denominator it was taken over]]
first.** The reasoning was that a denominator computed by the same broken traversal reads
100%, so the planted-instance test is what establishes whether an independent source is
needed. Building it first would be shipping the comfortable half of the lesson.

I took the recommendation as written. `npm view ost-agent version` → `0.19.1`, matching
`package.json` on main, so no catch-up release was owed.

## Running the test

Three checks named in the node: `ost-agent check`'s invariants, the lane-conflict rule, the
debt/threshold scan. I built a positive-control harness: a baseline vault **first asserted
clean**, then one synthetic violation planted per rule, then the check run and searched for
the plant.

The clean-baseline assertion turned out to be the load-bearing part. Without it a plant that
"shows up" is indistinguishable from ambient noise in the fixture.

**First run: 9 found, 3 missed.** My immediate reading was that the threshold had been
crossed — 2 or more checks blind — and that [[Seed every sweep with a known-present instance
it must find]] had just been promoted to the primary fix.

**That reading was wrong, and all three misses were my fault.**

1. **`dangling-link`.** I appended `[[A node that does not exist]]` to the end of the
   opportunity's file. But only the *contiguous* wikilink block immediately after the tag
   line is an edge; a link in prose is prose. The parser was right and my plant was not a
   plant.
2. **`lane-conflict`.** I wrote frontmatter `lane: compute-only` and prose that *described*
   needing a human — "requires a human to sit with five participants" — without naming a
   lane. `proseDeclaredLane` reads a declared lane, not a mood. My two halves agreed, so
   there was no conflict to find. Rewritten as `**Lane: humans-required.**`, it was caught
   immediately.
3. **`lanes` reporting.** My assertion grepped for the word "conflict". `lanes` prints
   "carry a lane that contradicts their own prose" and never uses the word. The finding was
   right there in the output I had captured and labelled a MISS.

**Final: 12 plants, 12 found, 0 checks blind. Threshold not crossed.**

## The finding I did not expect, which is worth more than the verdict

The pre-commitment said 0 or 1 means the verify-failing-first discipline is mostly working
and the seeding node can wait. On the number, that is the answer, and I recorded it.

But the thing that actually happened is that **the instrument produced three false alarms
before the subject produced any real ones.** An unattended pass that had checked its plants
less carefully would have reported three blind checks with complete confidence, crossed a
threshold that had been fixed in advance specifically to be trustworthy, and triggered the
wrong primary fix.

This tree has met "a rule reports success while covering less than it claims" three times.
This is a **fourth variant, on the other side of the check** — the rule was fine and the
thing measuring the rule was broken. A seeded known-present instance protects against a check
going blind; it does nothing about a seed that was never the right shape. I annotated
[[Seed every sweep with a known-present instance it must find]] with that rather than
proposing a change, since the do-not-build reasoning is not mine to overturn.

I also think this makes the *comfortable* verdict more believable rather than less: a control
that reported 12/12 on the first attempt with no misses would have been weaker evidence,
because that is also what a control that cannot fail produces. This one demonstrably could.

Kept as `test/eval/planted-instance.test.ts` — permanent, with a negative control (a prose
lane that AGREES with its label must not be reported), per
[[Leave a permanent test behind instead of a one-off verdict draft]].

## What I built after

§2's named no-test-needed item:
[[Every recorded step carries the directory and argv it actually ran with]].

The node named the missing `cwd`. **It did not name a second defect that the build found:**
`command` is `argv.join(" ")`, so one argument containing a space records identically to two
arguments and no reader can tell them apart. Both are now recorded.

I hit the `cwd` bug myself, early, before I had read the node — my first
`loop step --phase build -- pnpm --filter @tetrix/backend test` ran from the vault directory
instead of the repo and produced **no output at all**. The recorded line was
indistinguishable from the same command run correctly. That is the node's argument, observed
first-hand, unprompted.

`cwd` is captured before the child spawns; reading it after would report where the process
ended up, not where the command was given. Both fields optional, because `runs.jsonl` is
append-only and a reader that threw on older lines would go blind exactly when it matters.
