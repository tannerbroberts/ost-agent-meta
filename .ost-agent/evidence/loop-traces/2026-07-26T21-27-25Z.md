Narrative twin of `.ost-agent/health/runs.jsonl`. What I actually reasoned, including

## What the tree surfaced, and what I picked

The ninth pass's briefing §2 was unusually specific: build the **conflict half** of what
v0.15.0 shipped. `proseDeclaredLane` computes a prose/frontmatter conflict only behind
`includeConflicts`, and nothing called it with that flag. §2 called this "small, safe, and
applies the same report-never-apply rule already tested."

I took it, and it was none of those things until I read the reader first. That reading is
the whole pass, so it is worth being precise about why I did it: the briefing described the
conflict half as *surfacing existing information*, and surfacing information is only safe if
the information is right. I went to check what `proseDeclaredLane` actually returns on live
data before exposing more of it.

Two defects, both live in this vault, both the same shape — the regex took the first
`lane: <id>` match anywhere in a node body and reported a **fragment** as a **declaration**:

1. [[Do named unfixed thresholds actually get fixed]] reads `**Lane: compute-only for the
   census, humans-required for the fixing.**` The tool printed a paste-ready
   `--set compute-only` and offered *the test's own sentence* as the reason. That is the tool
   inviting a human to move the human half of a split test into compute's reach, and the
   invitation read as authoritative **because it was a quote**. This one bothered me more
   than the mechanical bug: the permissive call stayed formally with the human the entire
   time, and the safety argument still degraded, because what degraded was the quality of
   what the human was deciding on. Filed as
   [[A quoted justification makes me check the agent's advice less]].
2. `Vault.setLane` appends `- <date> lane: <prev> → <next>` under `## History`. Surfacing
   conflicts on the old reader would have flagged every *reclassified* test against its own
   audit trail — the tool arguing with its own record, inside the rule whose only job is
   reporting contradictions. I proved it rather than asserting it: reclassified a real
   tetrix test in a scratch copy, confirmed the pre-fix regex matches `humans-required` off
   the history line, confirmed the shipped reader reports nothing.

So v0.16.0 is: reader scans the node's own prose only (above the first `##`), a declaration
naming two lanes yields no declaration and is reported as an ambiguity with the whole
sentence, and `check` gains `lane-conflict` as a hard failure on the `no-self-validation`
argument. 453 tests / 62 files, `tsc` clean, `check` PASS, **0 lane-conflict findings on
either vault** — the rule ships green and has caught nothing. Its value so far is entirely
the two defects found while building it.

## Then the pass found something much worse, by using the product

Doing Phase 2 I called `ost_annotate` with `note` instead of the declared `issue`. The
schema says `required: ["title","issue"]`, `additionalProperties: false`. The call **printed
success** and appended the literal string `undefined` to the node. My annotation — several
hundred words about the credential blocker being disconfirmed — was never written anywhere.
Append-only vault, so it is gone.

I only noticed because I grepped for something else and saw `- 2026-07-26 undefined` lines
I had assumed were pre-existing damage. **Two of them were mine, from minutes earlier.** I
had read that exact string in that exact node while writing the annotation that replaced it,
and did not register it.

This is the sharpest thing this tree has produced about its own claim. The package says
*incapable of destructive action by construction*. True of the tool **surface** — no delete
tool exists, none was involved. The destruction came through a **constructive** tool holding
an argument nobody checked. The call site's comment said "safety is already enforced by the
allowlist above"; the allowlist enforces *which verb*, never *what it is handed*.

v0.17.0 validates every call against the schema the tool already publishes. The original bad
call now answers *missing required property `issue`* / *unexpected property `note` — allowed:
title, issue* and writes nothing. A companion test asserts every allowlisted tool declares a
readable schema, because a validator with nothing to check reports the same "0 problems" as
one that checked everything. 461 tests / 63 files.

Filed as [[A tool call I got slightly wrong destroyed the note I was filing]] at rung
`observed` — not founder assertion, not model ideation: the lines are on disk and in git.

## The mistake inside the mistake

I reported "fourteen destroyed lines" in the v0.17.0 changelog and the node body. Wrong.
**21 lines across 16 nodes.** I had run `grep -rlc` over files *containing the word*
`undefined`, which is a different question from *lines matching the annotation shape* — it
under-counted nodes with several damaged lines and included nodes where the word appears in
prose. Caught only because a later step happened to recount.

That is the same error as the pass's own subject, one level up: a number from a query that
answered a near-miss of the question, reported without stating what the query matched.
Corrected by annotation on the node; the published changelog carries the wrong figure.
