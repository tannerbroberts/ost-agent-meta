#Opportunity #unvalidated #evidence/assertion
[[One human dismissal can name a class of evidence rather than a single id]]

**The need, from the operator's side.** My highest-volume evidence channel produces many records of one recurring event. Discharging them is priced per record and paid by me: either I distil each into a node — forbidden, because they are the same claim — or I dismiss each by hand. Eighty-seven items is eighty-seven acts, and the channel manufactures more while I work.

**Measured, not felt.** `ost_next_work` reported **87 unmapped evidence items** this pass. Two came from `friction/` and carry distinct content. The rest are `TRANSCRIPT:` session-friction records, and reading them shows the shape: this node's own source records ten events, six `tool_error` and four `retry`, and four of the six are one sentence — a permission the unattended surface does not hold. Dozens of sibling records say the same thing about different session ids.

**What already exists, verified against the code rather than assumed.** `ost-agent dispose --kind evidence <id> --by <who> --why <reason>` ships and is pinned by `test/cli/dispose.test.ts`. It refuses an unattributed or unexplained dismissal, prints the reversal command beside the confirmation, keeps the entry append-only so a reversal does not erase the dismissal, and `ost-agent dispositions` lists every live one for audit. `ost_next_work` reads it back as `withheldByDisposition`. So the escape hatch is real, it is well built, and this node is not asking for one.

It is also deliberately a human's command and should stay one. A dismissal removes work by asserting a sentence about it, written by the party whose budget the work costs; the spec file says exactly that, and it is the same argument that keeps `result` and `promote` off the agent surface. Nothing here should be read as an argument for handing dismissal to a pass.

**What is actually missing is the unit.** The mechanism dismisses one id per invocation, and the thing an operator has is a *class* — "session-friction records whose only content is a permission this surface does not hold". Paying per member for a judgement made once about the set is the gap, and it is the gap that scales the wrong way: transcripts are generated by the loop itself, so every firing that hits friction manufactures another member, and the queue grows from being worked.

**Why mapping cannot absorb the class either.** `src/processes/tree.ts` states the relation in its own header: *"evidence is mapped iff some node in the tree cites its id as that node's `source`."* One writer, `ost_create_node`'s `source`, a single string in node frontmatter. A distillation that genuinely covers forty records can only cite one of them, so thirty-nine stay outstanding even when the reasoning that discharges them has been done and written down. The doc comment explains — correctly — why the *persisted* mapped-set was deleted: a reader with no writer was a second answer any actor could forge. Deriving the relation was right; deriving it from a one-to-one field is what leaves the other thirty-nine.

**Whose problem this is.** Not only this vault's. Any operator who turns on a mechanical channel — transcripts, usage, a webhook — buys a stream where most records restate one fact. Manual inbox notes do not have this property, which is why the tree did not have it for its first fortnight.

**More than one way to address it**, so it is not a solution in disguise: let one human judgement cover a named class of records; let a node cite many sources; or roll near-identical records into one before they are ever stored. Those are different products with different failure modes, and the first two disagree about whether the answer is dismissal or distillation.

**What this does not claim.** It is first-party throughout — a count off this tree's own tool output and reads of this product's own source and specs. No outside operator has reported it. Rung is the floor, deliberately: the source is a `TRANSCRIPT:` recording and would carry `observed`, but the recording evidences the agent's tool errors, not this claim about evidence accumulation, and taking the higher rung on that technicality would be exactly the laundering the ladder exists to stop.

⚠️ Unvalidated. Agent-distilled.
