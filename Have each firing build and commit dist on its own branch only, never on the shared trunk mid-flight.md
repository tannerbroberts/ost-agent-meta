#Solution #unvalidated #evidence/assertion

Leave dist/ checked in and built normally, but change when it's committed: build and commit it only as the last step before a branch merges to main (via the normal review/merge path), never as an intermediate commit a concurrent firing's auto-merge might cross. Serializes the one place two branches actually touch the same generated bytes.

**Compared to the alternatives.** No new tooling (no build-time dependency at merge, no custom merge driver) — just a process change to when the commit happens. Weakest of the three at actually preventing the conflict, since it only removes the *intermediate*-commit case and two branches still legitimately finishing around the same time can still collide at the real merge point.
