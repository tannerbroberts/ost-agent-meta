#Assumption #unvalidated #evidence/assertion

**Kind: feasibility.**

**The belief, stated so it could be false.** A flag is worth having only if the writer cannot set it. This candidate assumes the tool can determine, from its own configuration and grants, whether repo sight was available — without asking the caller. If the only available source is a parameter the agent passes, the flag records a claim rather than a fact, and an agent motivated to clear a backlog is precisely the party being asked.

The observed case makes this concrete and awkward: sight failed on this surface in two different ways on the same day — `ost_read_repo` refusing for want of `product.repos`, and the harness denying a direct filesystem read of the checkout. Only the first is visible to the tool. A pass with a configured repo but a denied filesystem grant would be marked grounded and be just as blind.

**What would make it false.** No signal available at the tool boundary distinguishes a pass that read the code from one that did not.
