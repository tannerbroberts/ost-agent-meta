#Assumption #unvalidated #evidence/assertion
[[Show five operators a pass's dismissed-work list and ask whether they would have let it stand]]

Desirability, and the one that should decide whether this candidate ships at all.

Every other way an item leaves the work list requires the agent to do something checkable — ship code, attach an instrument that fails today, create a node. A disposition removes it by writing a sentence. The party writing that sentence is the party whose budget is spent by the work it dismisses, which is a live incentive rather than a theoretical one.

Stated so it can be false: an operator who is not watching may simply not accept a mechanism whose failure mode is an agent quietly declaring itself finished, however good the audit trail is — in which case the review surface is not a mitigation but a consolation, and the two derivation-based siblings are the only acceptable answers because they cannot be talked into anything.

This is not a question the repository can answer. No spec can tell anyone whether a person would trust the mechanism; the code would pass whatever a person thinks of it.
