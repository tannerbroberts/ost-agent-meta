#Assumption #unvalidated #evidence/assertion

**The belief, stated so it could be false.** A dismissal that records who skipped the item, why, and when — reversibly, and listable in one command — gives a human enough to catch bulk or dishonest skipping after the fact, which makes it safe to let an unattended agent skip at all.

**Kind.** Viability, in the trust sense: whether the permission can be granted without giving away the property the product is built on.

**How it could turn out false.** After-the-fact auditability only works if someone audits. The operator this tree is for is one whose stated constraint is that their hours do not exist — the whole bucket "I need the tree's output to be actionable by compute alone, because my hours don't exist" says so — and a review queue is exactly the kind of obligation that never gets served. If nobody reads the dismissal log, the reason string is not a check, it is a formality the dismissing party writes to itself, and the mechanism has granted an unattended agent the ability to declare work worthless in order to reach `done`.

**Why it is the riskiest one here.** The plumbing is a flag and a string. Whether the audit trail is a real restraint or a comfortable fiction is the entire question, and it is not answerable by building it.
