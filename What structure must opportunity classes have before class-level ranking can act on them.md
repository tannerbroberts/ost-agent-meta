## Answer

Desk work over the vault itself, per this node's Methodology, by the 2026-08-10 unattended sweep. Unvalidated — per the Methodology's own closing line, a human confirms this before anything is built.

**(1) Is the existing category-bucket layer sufficient structure for class-level ranking? No.** Checked act by act against what a parent edge can express: a bucket is a parent edge, and the tree enforces exactly one parent per node (`ost_link_nodes` refuses a second edge; check rule single-parent). Three of the directive's acts exceed that: (a) *membership* — a class member may belong to several classes, and this is already observed, not hypothetical: "The agent can decompose my goal but cannot acquire and test its own guesses about how to reach it" carries both `founder-theory` and `needs-customer-interview` while its one parent edge is spent on its bucket; (b) *cross-layer reach* — a real class covers Solutions as well as Opportunities (see the worked example), and buckets file only opportunities; (c) *rank in one recorded act* — a cross-cutting class has no bucket node to record the act on, so under parent edges alone the act has nowhere to live.

**(2) The minimal structural addition, named concretely: compose two mechanisms the vault already has, and build no new node type.** Membership = a shared class *tag* on member nodes — the mechanism is already in live use (`founder-theory`, `self-organization`, `needs-customer-interview`). Ranking and versioning = one *class-definition node* per class, whose append-only `## History` is where each rank, re-rank, or reclassification act is recorded once, dated, with its reason — which is also what keeps a corrected misconception legible instead of erased. Members are found by tag scan at read time, never listed as wikilinks on the definition node (the one-backlink rule reserves brackets for the parent edge, and a derived list cannot go stale). The only genuinely new thing to build is a reader — rollup or next_work resolving tag → members when it encounters a rank act.

**(3) Worked example — the class `founder-theory`, real in this tree today.** Members by tag scan: the Opportunities "The agent can decompose my goal but cannot acquire and test its own guesses about how to reach it" and "The goal I care about is too far from anything I can act on this week" (different buckets), and the Solutions "Versioned reclassification that moves a node while keeping every prior self readable" and "Weave corrected misconceptions into the map as legibly closed roads". One recorded act on the class-definition node — e.g. "down-rank: founder-theory members rank below any opportunity holding a non-founder artifact, until corroborated" — would change the standing of all four members at once without touching any parent edge, would be reversed by appending a later act rather than editing, and when a member is later corroborated it leaves the class by dropping the tag, with the departure dated on its own History. Under parent edges alone this act is impossible: the four members share no parent.

**Consequence for the darkened node.** The three solutions beneath "An opportunity built on a misunderstanding has nowhere to go, because the tree can only add beside it" gain a shared prerequisite: the tag-plus-definition-node convention above. They can be designed against it now; none of them needs to invent membership structure of its own.
