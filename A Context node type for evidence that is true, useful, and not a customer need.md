#Solution #ported-from-ost-agent-vault #evidence/assertion
[[Count stranded evidence items across both vaults that only a Context node could home]]

**The idea.** Add a node layer for discovery products that are neither opportunity, solution, nor test: existing de-risked capability, hard constraints, unresolved factual conflicts, open human decisions. Things that are true and that should shape ideation without pretending to be needs.

**The evidence: both instances invented the same workaround.** Given nowhere to put this material, both agents dumped it into the root Outcome's body and Issues section. The tetrix Outcome node is now 10KB and carries seven annotations covering: an argument that the outcome is stated as a lagging business metric rather than a product outcome; a standing caveat that no node in the tree is interview-sourced; an unresolved factual conflict about whether the product has zero users or a handful; a capability gap in top-of-funnel measurement; a tension between a $5/month price and a "Free, Ad-Free" market position; the permanently-unmappable evidence item; and the builder briefing. Seven unrelated concerns, four distinct kinds, one node, appended in the order they occurred to the agent.

Every one of them is genuinely valuable. That is what makes this a schema problem rather than a discipline problem — the agent was not being sloppy, it was doing good work with one drawer.

**Two things this fixes at once.** It gives the termination problem a legitimate destination: evidence that maps to Context is *mapped*, not declined, and the ledger clears honestly. And it stops the root node — the one thing every reader opens first — from being where all unclassifiable output accumulates until nobody reads it.

**The strongest argument against.** Torres's method is deliberately spare, and every new node type is a place for an agent to file something rather than think about it. "Context" is a broad enough label to become a junk drawer, at which point the material is still unsorted, just no longer in the Outcome. The seven tetrix annotations suggest the real distinctions might be sharper and fewer — *constraint*, *open question for a human*, *existing capability* — and that picking those deliberately beats one catch-all. Worth resolving before building.

**Note the operator's own vote.** The human editing this vault reached for `type: Metric`, a type that does not exist, and the node silently vanished from `ost_read_tree`. Three independent parties have now wanted a node type the schema lacks.
