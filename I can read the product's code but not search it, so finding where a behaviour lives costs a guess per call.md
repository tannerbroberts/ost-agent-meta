#Opportunity #unvalidated #evidence/observed
[[Widen the harness's existing file-read grant to the product path instead of building any search]]

**The need:** "I can open any file in the product's source and list any directory, but I cannot ask where something is. So every question of the form *which module does X* becomes a sequence of guessed paths, each costing a call, and a question one `grep -rn` would answer can be unanswerable no matter how many calls I spend."

**Why this is not the layout need beside it.** The sibling "I probe for files that were never there, because nothing hands me the layout of the workspace I am in" is about the workspace never being declared: the fix is handing over a map. This node is about the granted channel lacking a verb, and the two come apart cleanly in both directions. Hand over a complete layout and this need survives — knowing that `src/mcp/` holds nine files does not say which one renders a sentence, and reading all nine is the guessing this node is about. Add a search verb and the sibling survives — you can grep a repository whose layout you were never told. That is Torres's test passed in both directions, and it is stated here because a reader skimming titles could take them for one need. It is also distinct from "A string I meant literally is read as syntax, so the command fails instead of searching" and "I write a valid pattern and the tool rejects it, because it speaks a narrower regex than the one I know", which are about a search tool you *have* misreading your pattern.

**Observed cost, first-party and specific.** The parent's 2026-09-07 section records the sharpest instance: the errand asking whether any CLI entry point prints `proseDeclared` has been open across five passes, because `src/cli/index.ts` is 177,250 bytes and truncates on read, `src/cli` holds only three files so there is no smaller module to read instead, and the one thing that would settle it — `grep -rn "triageLanes" src/cli/` — is not expressible on the granted channel. The same section on "An operator-set evidence window in ost.config.yaml, amended by hand like discovery.target" records the `undefined`-formatter defect surviving eleven days and three firings for the same reason: `src/mcp/next-work.ts` probes at 102,950 bytes with `wouldTruncate: true`, and the settling command is again a one-line grep nobody on this surface can run.

**Two further instances, both from the firing that wrote this node.** Its own captured record `TRANSCRIPT:342c066c-216d-440b-9ba8-e2b1edace9c2` carries `ost_read_repo` refused on `"src/ost/verify.ts" does not exist` — a filename reached for because there was no way to ask where verification lives; the refusal helpfully listed the directory, which is the tool doing the best a listing-shaped surface can. And this firing then hit the truncation half itself: it read `src/eval/buildable.ts` to confirm first-party whether the `solutionsMissingInstruments` bucket applies a lane check, and the file truncated at exactly the function that would have answered it, leaving the claim resting on a prior pass's read rather than on this one's.

**Why the cost compounds rather than being a one-off inconvenience.** A guessed path that misses is a `tool_error`, and this vault captures its own session transcripts as evidence. So each guess mints an evidence record that no Opportunity will ever be distilled from, which the branch under "I want my usage to automatically feed into and make the OST-Agent better" has censused as the mechanism by which the queue grows without carrying new needs. The missing verb is therefore upstream of a queue-length problem, not only of a wasted call.

**Litmus test (more than one way to address?):** Yes, and they trade off against each other. Add a search verb to the repo channel. Grant the harness's own file tools on the product path, so the existing grep reaches it. Ship a symbol-or-path index the agent reads once per pass. Have the loop precompute a repo map into the firing prompt. Return matching filenames only, without line content, as a narrower and safer verb than full grep. Distinct mechanisms with real differences in cost, blast radius and who maintains them. Passes.

**What this node does NOT claim.** It takes no position on whether a search verb *should* be added — widening what a read-only surface can do is a decision with its own risks, and this node records the need rather than proposing the answer. It is also observed behaviour of this product's own agent, so it grounds usability and feasibility, never desirability: nothing here is evidence that anybody outside this building wants it.

**Provenance caveat.** Every instance above is this vault's own unattended firing, captured mechanically from session transcripts. That is a recording rather than a claim, which is why the rung is `observed`, and it is a recording of one actor — the agent itself — which is why it is not corroboration by independent voices.
