#AssumptionTest #unvalidated #evidence/assertion

**Lane: humans-required.** Pull ten instruments already in this tree. Strip authorship and dates. Have a reader who does not know the provenance rate each one: does its assertion describe behaviour that exists and is wrong, or does it only require a file to be created? Then reveal which passes had repo sight and compare.

**Run this before building the gate, not after.** The assumption it tests already has counter-evidence sitting in the tree — the 2026-08-06 sweep had no repo sight and wrote two grounded instruments out of three, which is the proxy over-blocking in a sample of one pass. If a wider read confirms that, the gate is a tax rather than a filter and the parent solution should lose to the alternative its own assumption names: require an instrument's author to state which kind of red it is, and check that the statement is there.

**Why no command can settle this.** "Grounded" is a property of what an assertion means against a codebase, not of any exit code. An instrument that names a missing file and one that names a broken mechanism both exit non-zero today; that is exactly why the distinction has to be read rather than run, and why a passing suite would tell nobody anything about it.

This tree's mandate says no node may climb the believability ladder on founder or model sources alone. A model rating instruments written by a model is the reflexive case, so the reader should not be either.

A person outside the building is the measurement here: A person is irreducibly the measurement: someone must read ten existing instruments cold — without knowing which pass wrote them or whether it had repo sight — and judge each as grounded-in-a-real-mechanism or merely-naming-a-missing-file. That judgement is what the proxy is being scored against, so a command that made it would be scoring itself.
