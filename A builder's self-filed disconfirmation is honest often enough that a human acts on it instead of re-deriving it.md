#Assumption #unvalidated #evidence/assertion
[[The operator judges the next five builder-filed disconfirmations against their specs and counts the honest ones]]

**Kind: viability, with a harm check attached.** The channel is worth building only if what comes through it can be acted on. A builder that cannot make a spec pass has a standing incentive to call the red a refutation, and the structure (bar cited, value cited) narrows but does not remove that. The one recorded instance was honest — "fails by design and should not be loosened" — but n=1, and the builder that wrote it was also the one that had just spent a firing failing.

**Stated so it could be false:** of the next five disconfirmations a builder files, a human reading the spec and the numbers judges at least four to be genuine refutations rather than a builder excusing an unfinished build.

**What would change if it were false.** The channel becomes noise a human must re-check every time, which is the state the report file is already in; the counting sibling ("After two builds leave an instrument red…") carries the need instead, because it trusts no account.

**Not answerable from the repository.** Honesty of a judgement is judged by a person reading it; no exit code holds it.
