#Solution #unvalidated #evidence/assertion
[[Claim and commentary separate mechanically without a reserved section landing in the unread half]]

**Variation dimension: automated-vs-manual. Position taken: the split and the routing are automated; deciding what earns a place in the claim stays manual.**

The node stops being one document. A claim file holds the need or candidate and its current reasoning; a commentary file holds every dated section, examination note and census. Appends land in the commentary automatically, with no judgement at write time. `ost_read_tree` returns the claim; the commentary comes back only when asked for. Nothing is deleted and nothing is summarised — the material moves, and the default read stops paying for it.

**Why the manual half is the point rather than a shortcut.** What deserves to be in the claim is the one thing no mechanism can decide: it is the difference between a finding and a record of looking, and that is a judgement about meaning. Any automatic promotion rule would either pull commentary back in by keyword — reintroducing the bloat with extra steps — or leave real corrections stranded in a file nobody opens. So promotion is a person's edit, made when they are already reading the node, and the automated half only guarantees that the default read is cheap.

**Against the siblings.** Unlike the candidate that suppresses the append, nothing is lost and nothing depends on a pass judging its own output correctly — a note written for the wrong reason costs a file entry rather than a reader's budget. Unlike the bought compactor, the claim is served verbatim rather than as a lossy rendering, so nothing a reader acts on has been through a paraphrase.

**What it does that neither sibling does.** It repairs the existing corpus. The 1,596 nodes already written can be split mechanically on their own section boundaries — this tree's bloat is unusually tractable because the commentary is already self-labelling, arriving as dated `## ` sections beneath the original body.

**What it costs, plainly.** A node becomes two files, so every count, link, gate and check has to decide which half it means, and getting that wrong is how a reserved `## Results` block ends up in the half nothing reads. That is the sharp edge: this product's strongest guarantee is that a human's recorded finding survives every rewrite, and a scheme that moves material between files is the most plausible way to break it by accident. Reserved sections would have to be pinned to the claim half by construction, not by convention.

**What would make this the wrong pick.** If readers routinely need the commentary — if the dated sections turn out to be where the actual findings live and the opening paragraph is the stale part — then this hides the good half and the default read gets worse while looking better. That is a real possibility here: several of this tree's most substantive measurements are in appended sections, not in the original bodies.

**Honest note on how this was ideated.** All three candidates under this opportunity were composed in one context by one author. The ruleset asks for one blind ideator per assigned dimension and this surface has no grant to run them, so discount their apparent distinctness accordingly.
