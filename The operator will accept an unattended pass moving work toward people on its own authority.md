#Assumption #unvalidated #evidence/assertion

**Kind: desirability.** The directional-safety argument says this write cannot hurt the tree. It does not say anyone wants it. A pass labelling tests humans-required is a pass adding to the operator's personal queue without being asked — the parent opportunity already reports 53 outstanding asks and 473 tests waiting on a person, so the plausible operator reaction is not gratitude but "stop putting things on my list."

Stated so it could be wrong: the operator would rather have an unattended firing record these verdicts itself, with the risk that some are wrong, than keep reading a queue where the deliberate and the outstanding are indistinguishable.

There is a real chance this comes back refuted, and the refutation would be informative: it would mean the parent's need is genuinely a *reporting* need — the two-counts sibling — rather than a verdict-recording one.

**Why no instrument can settle this.** No exit code encodes whether a person is willing to have their queue written to by a machine. The repository can pin what the tool does; only the operator can say whether they want it done.
